updates/

One file per change, named by date (with a suffix when there's more than
one that day). Each is a plain-text dev log: what changed, why, how it was
tested, and what's left. Read these to catch up on work that isn't obvious
from the diff alone - migration quirks, the reconcile_db step, decisions
that were reverted, etc.

The matching draft commit message for each file is in ../commits/ under the
same name.
