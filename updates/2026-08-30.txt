1. BACKEND - new `restaurant` app endpoints
================================================================
Routes (mounted at /api/ via goodFoodProj/urls.py -> restaurant.urls):

  POST /api/get-restaurant-info/   { account_id }
       -> { "restaurant": {...} | null, "location": {...} | null }

  POST /api/add-restaurant-info/   (multipart/form-data)
       fields: account_id, restaurant_name, restaurant_description,
               address, contact_number, email,
               city, province, region, country, latitude, longitude,
               restaurant_logo_img (file), restaurant_cover_img (file)
       -> { "message": "Restaurant information saved" } | { "error": ... }

backend/goodFoodProj/restaurant/queries.py
  - getRestaurantInfo(data)
      SELECT * the newest restaurant_restaurant row for the account, then
      SELECT * its location_location row. Returns both as plain dicts.
  - addRestaurantInfo(data)
      * validates account_id + the four NOT NULL columns
        (restaurant_name, address, contact_number, email)
      * saves restaurant_logo_img / restaurant_cover_img through Django
        storage, keeps only the path (a raw file can't go into SQL)
      * looks up the account's existing restaurant:
          - if found: UPDATE its location (or INSERT one if it had none),
            then UPDATE the restaurant. COALESCE(%s, col) keeps the current
            image when no new file was sent.
          - if not found: INSERT the location, then INSERT the restaurant
            with created_at = NOW().
      * so the screen works as both "create" and "edit".
      * duplicate restaurant email -> IntegrityError ->
        "That email is already used by another restaurant".

  Written to match account/queries.py exactly: one self-contained function
  each, `connection = connections['default']` + `cursor`, inline SQL strings,
  `columns = [col[0] for col in cursor.description]` / `dict(zip(...))`,
  try / except IntegrityError / except Exception / finally that closes the
  cursor and connection, explicit connection.commit(). No helper functions,
  no module-level column constants (an earlier factored version was reverted
  for being harder to read).

backend/goodFoodProj/restaurant/views.py
  - GetRestaurantInfo  (AllowAny)                -> getRestaurantInfo
  - AddRestaurantInfo  (AllowAny, MultiPart/Form) -> addRestaurantInfo

Note on the `account` app: the two functions / views / routes briefly lived
in account while the feature was built, then moved here. account/queries.py,
account/views.py and account/urls.py end up unchanged apart from trivia.
checkInfoIfComplete stays in account - it reports BOTH personal and
restaurant onboarding status.

2. FRONTEND - the screen
================================================================
frontend/src/screens/Owner/RestaurantInformationScreen.js  (rewritten)
  Was a broken copy of the personal-info screen (every input bound to
  form.lastname, leftover gender dropdown + date picker). Now:
  - three small module-scope components: TextField (explicit label / value /
    onChangeText props), LogoField (circular + camera badge), CoverField
    (wide banner), plus a chooseImage(onPicked) helper.
  - the body is a flat, scannable list - one <TextField> per field.
  - ScrollView (the form is long), Cancel -> goBack(), Submit shows a spinner
    while saving.

frontend/src/hooks/useRestaurantInfoForm.js  (new)
  - a single FIELDS array drives the empty form, the prefill, the submit
    body and the required-field check.
  - on mount, calls getRestaurantInfo(); if a restaurant exists it fills the
    form + shows the saved logo / cover (edit mode).
  - validates the four required fields + email format.
  - builds multipart FormData with account_id + all text fields; only a
    freshly picked LOCAL image is uploaded (an unchanged remote one is not
    re-sent).
  - on success: Alert -> navigate to RestaurantHome.
  - small helpers (labelFor, readAccountId, appendImage) at the bottom.

frontend/src/api/services/home.js
  - new getRestaurantInfo() and addRestaurantInfo(formData).
  - extracted a shared postMultipart(path, formData) helper (explicit
    multipart header, 20s timeout, "server error" vs "can't reach server"
    messages); addAdditionalInfo() now uses it too.
  - added a currentAccountId() helper for the JSON POST bodies.

frontend/src/navigation/AppNavigator.js

frontend/src/screens/Owner/RestaurantHomeScreen.js
