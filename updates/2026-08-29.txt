NEW FILE: frontend/src/constants/config.js
================================================================
Central place for backend URL config. Exports:
  - BACKEND_API_URL  : from react-native-config (.env)
  - BACKEND_ORIGIN   : API URL with a trailing "/api" stripped (used for media)
  - mediaUrl(path)   : turns a stored media path like "account_photos/19.jpg"
                       into a full URL
                       (http://<host>:8006/media/account_photos/19.jpg).
                       Values that are already absolute (http/https, file://,
                       content://, data:) are returned unchanged.

1. FIX — "Add Information" (owner personal info) never reached the database
================================================================
Files: useAddInformationForm.js, RestaurantProfileInformationScreen.js,
       backend account/queries.py

Problems found
  - The request never included `account_id`, so the backend ran
    "UPDATE ... WHERE account_id = NULL", matched 0 rows, and still
    returned a success message.
  - Gender was captured from the dropdown as an updater FUNCTION, not a
    string (react-native-dropdown-picker calls setValue with a callback).
  - Selecting a photo crashed the backend: the raw uploaded file object was
    passed straight into a SQL parameter, and the file was never saved to
    MEDIA_ROOT.
  - birthdate was sent as a locale string ("8/29/2026") instead of
    YYYY-MM-DD.
  - On success it navigated to "RestaurantHomeScreen", which is not a
    registered route (the route is "RestaurantHome").

Changes
  Frontend
  - Read `account_id` from the cached user in AsyncStorage and append it to
    the form data.
  - Pass `setGender` straight to GenderDropdown; submit now reads the gender
    state (merged into a `payload` object for validation + send).
  - Format birthdate as YYYY-MM-DD from the selected Date (toISODate helper).
  - Alert and stop if there is no signed-in user.
  - Navigate to the real "RestaurantHome" route on success.
  Backend  addAdditionalInfo()
  - Require `account_id`; return {"error": "account_id is required"} if missing.
  - Save an uploaded photo through Django's default_storage and store only the
    path in the DB.
  - account_profile_photo = COALESCE(%s, account_profile_photo) so an existing
    photo is kept when none is uploaded.
  - Return {"error": "Account not found"} when 0 rows match, instead of a
    false success.

2. HARDENING — "Network Error" when pressing Submit
================================================================
Files: api/services/home.js, useAddInformationForm.js,
       RestaurantProfileInformationScreen.js

  - addAdditionalInfo() now sends an explicit `multipart/form-data` header and
    a 20s timeout, logs transport failures (url, error code, message), and
    throws a readable message that distinguishes "server returned an error"
    from "could not reach the server".
  - The image picker keeps the whole asset object ({ uri, fileName, type })
    instead of only the uri, so uploads use the real filename and mime type,
    and didCancel / errorCode results are handled.

Investigation notes (for reference)
  - Backend verified reachable; all endpoints return 200 from curl, including
    multipart add-additional-info.
  - The .env value http://10.14.20.225:8006/api is correctly baked into the
    debug APK's BuildConfig.
  - JSON POSTs from the app work. The failure is specific to the multipart
    request — most likely the attached photo's uri not being readable by the
    native uploader, which aborts the request.

3. FEATURE — stay logged in after a refresh/restart, expire after 1 day
================================================================
Files: api/services/auth.js, SplashScreen.js, useLoginForm.js,
       RestaurantProfileScreen.js, DinerProfileScreen.js

  auth.js
  - login() now also stores a "loginAt" timestamp alongside the tokens/user.
  - NEW getActiveSession(): returns the stored session only if it is younger
    than SESSION_TTL_MS (24h); otherwise clears storage and returns null.
  - NEW clearSession(): removes accessToken, refreshToken, user, loginAt.
  SplashScreen
  - On boot, calls getActiveSession() and navigates straight to RestaurantHome
    / DinerHome (by account_type) when a valid session exists; only falls back
    to Login when there is none or it has expired. Splash still shows ~1.5s.
  useLoginForm
  - On success, resets the navigation stack to the home route so Splash / Login
    are not left underneath it.
  Both profile screens
  - Logout now goes through clearSession() (also clears loginAt).

Behaviour
  refresh / restart within 24h of login   -> stays logged in, jumps to home
  refresh / restart 24h+ after login      -> session cleared, back to Login
  tap Logout                               -> session cleared immediately

To change the window: edit SESSION_TTL_MS in api/services/auth.js.
Note: this is a client-side timer; all API endpoints are still AllowAny.

4. FIX — uploaded profile photo not visible on the Profile screen
================================================================
Files: RestaurantProfileScreen.js, DinerProfileScreen.js,
       useAddInformationForm.js, backend account/queries.py

Cause
  The photo IS saved on the server correctly, but the DB stores only a
  RELATIVE path ("account_photos/19.jpg"). The profile screens passed that
  straight into <Image source={{ uri: ... }}>, which React Native cannot
  resolve, so the avatar rendered at 0x0 (which also collapsed the layout and
  made the name/email look centered).

Changes
  - Profile screens build the avatar URL with mediaUrl(), falling back to the
    bundled `pfp` image.
  - Cached user is re-read on screen focus (useFocusEffect) instead of once on
    mount, so a newly saved photo shows when returning to the Profile tab.
  - Backend addAdditionalInfo() UPDATE gained a RETURNING clause; the endpoint
    now returns the updated user row.
  - The hook merges that returned user into AsyncStorage after a successful
    save, so the new photo/details appear without logging in again.
  - The Information screen now prefills first/last name, gender, birthdate and
    the current photo from the cached user (works as an "edit" screen). On
    submit, only a freshly picked LOCAL file is uploaded; the existing remote
    photo is not re-sent (isLocalFileUri guard).
