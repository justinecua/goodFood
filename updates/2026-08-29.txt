config.js

One place for the backend URL. Exports BACKEND_API_URL (from
react-native-config / .env), BACKEND_ORIGIN (the same URL without the
trailing /api, for media), and mediaUrl(path), which turns a stored path
like "account_photos/19.jpg" into a full http://host/media/... URL. Paths
that are already absolute (http, file:, content:, data:) are passed through.


1. "Add Information" never reached the database

Several things were wrong at once:
- account_id was never sent, so the backend ran UPDATE ... WHERE
  account_id = NULL, matched nothing, and still returned success
- gender came from react-native-dropdown-picker as an updater function, not
  a string (it calls setValue with a callback)
- picking a photo crashed the backend - the raw file object went straight
  into a SQL parameter and was never written to MEDIA_ROOT
- birthdate was sent as "8/29/2026" instead of YYYY-MM-DD
- on success it navigated to "RestaurantHomeScreen", which isn't a real
  route (it's "RestaurantHome")

Frontend: read account_id from the cached user and send it; pass setGender
straight to the dropdown and read the gender state on submit; format
birthdate as YYYY-MM-DD; bail with an alert if nobody is signed in; navigate
to "RestaurantHome".

Backend, addAdditionalInfo(): require account_id; save the photo through
default_storage and store only the path; account_profile_photo =
COALESCE(%s, account_profile_photo) so an existing photo survives; return
"Account not found" on 0 rows instead of a fake success.


2. "Network Error" on Submit

Mostly hardening so the real cause is visible next time:
- addAdditionalInfo() sends an explicit multipart/form-data header and a
  20s timeout, logs transport failures (url, code, message), and throws a
  message that separates "server returned an error" from "couldn't reach
  the server"
- the image picker keeps the whole asset ({ uri, fileName, type }) instead
  of just the uri, and handles didCancel / errorCode

What we know: the backend is reachable and every endpoint returns 200 from
curl, including multipart. JSON POSTs from the app work. The failure is
specific to the multipart request with a photo attached - most likely the
asset uri not being readable by the native uploader. The .env IP is baked
into the APK correctly.


3. Stay logged in across a restart, expire after a day

auth.js: login() also stores a loginAt timestamp. New getActiveSession()
returns the stored session only if it's younger than SESSION_TTL_MS (24h),
otherwise it clears storage and returns null. New clearSession() wipes
accessToken, refreshToken, user, loginAt.

SplashScreen calls getActiveSession() on boot and jumps straight to
RestaurantHome / DinerHome (by account_type) when the session is valid;
it only falls back to Login when there's none or it expired. Splash still
shows for ~1.5s. useLoginForm resets the nav stack to home on success so
Splash/Login aren't left underneath. Both profile screens log out through
clearSession().

  restart within 24h   -> stays logged in, goes to home
  restart after 24h    -> session cleared, back to Login
  Logout               -> session cleared now

This is a client-side timer only; every API endpoint is still AllowAny.
Change the window with SESSION_TTL_MS in api/services/auth.js.


4. Saved profile photo not visible

The photo is stored fine, but the DB keeps only a relative path
("account_photos/19.jpg") and the profile screens passed that straight into
<Image source={{ uri }}>, which RN can't resolve - so the avatar rendered
at 0x0 and collapsed the layout around it.

- profile screens build the URL with mediaUrl() and fall back to the
  bundled image
- the cached user is re-read on focus (useFocusEffect), so a new photo
  shows when you come back to the tab
- addAdditionalInfo()'s UPDATE got a RETURNING clause; the endpoint returns
  the updated row and the hook merges it into AsyncStorage, so changes
  appear without logging in again
- the Information screen prefills name / gender / birthdate / photo from the
  cached user and works as an edit screen; on submit only a freshly picked
  local file is uploaded, the existing remote photo isn't re-sent
