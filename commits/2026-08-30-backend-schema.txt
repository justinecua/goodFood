restaurant app
- add Restaurant_Branch, Category, Restaurant_Category
- add updated_at to Restaurant; PK is BigAutoField to match the real
  restaurant_restaurant.id bigint column
- queries.py now uses restaurant_id / updated_at (the raw SQL had `id`)

Details
- PK names follow the diagram (dish_id, branch_id, ...)
- on_delete: CASCADE for owned rows, SET_NULL for optional links,
  PROTECT for Subscription.plan
- DecimalField for money and ratings, ImageField for photos
- new apps registered in INSTALLED_APPS

Applying it to an existing database
The real DB predates this schema and restaurant.0001_initial is recorded
as applied (its file was regenerated), so migrate skips it and the
existing restaurant_* tables never get the changes. reconcile_db runs
reconcile_existing_db.sql to catch up - rename id -> restaurant_id, add
updated_at, create the three new tables:

    python manage.py reconcile_db
    python manage.py migrate

A fresh database just needs migrate. manage.py check is clean and a
fresh-DB migrate applies the whole graph.
